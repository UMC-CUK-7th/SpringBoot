# 🎯 핵심 키워드

- DI
    
    ### DI(Dependency Injection): 의존성 주입
    
    스프링 프레임워크가 지원하는 3가지 핵심 프로그래밍 모델 중 하나
    
    - 외부에서 두 객체 간의 관계를 결정해주는 디자인 패턴
    - 두 객체 간의 관계(의존성)를 맺어주는 것
        - 주입 방법: 생성자 주입, 필드 주입, 수정자 주입
    - 스프링 컨테이너에서 객체 Bean을 먼저 생성해두고 생성한 객체를 지정한 객체에 주입하는 방식
    - 인터페이스를 사이에 둬서 클래스 레벨에서는 의존관계가 고정되지 않도록 함
    - 런타임 시에 관계를 동적으로 주입하여 유연성을 확보하고 결합도를 낮출 수 있게 해줌
    
    **주입 방법**
    
    - 생성자 주입(Constructor Injection)
        - 클래스의 생성자를 통해서 의존성을 주입하는 방식
        - 인스턴스가 생성될때 1회 호출되는 것이 보장
        - 생성자 주입시 필드에 `final`  키워드 사용
    - 필드 주입(Field Injection)
        - 클래스에 선언된 필드에 생성된 객체를 주입하는 방식
        - 스프링에서 제공하는 `@Autowired`  어노테이션을 주입할 필드 위에 명시
        - 간편하게 의존 관계 주입이 가능하지만 참조 관계를 눈으로 확인하기 어렵고,
        순환 참조를 막을 수 없음
    - 수정자 주입(Setter Injection)
        - 클래스의 수정자를 통해서 의존성을 주입해주는 방식
        - Spring에서 `@Autowired`  어노테이션을 사용해서 Setter 메서드를 통해 주입하는 방식

- IoC
    
    ### Spring IoC(제어의 역전)
    
    프레임워크가 객체의 생성, 관리, 제어 흐름을 담당하도록 변경하는 개념
    
    - 제어의 역전: 객체의 생성, 생명주기의 관리까지 모든 객체에 대한 제어권이 바뀌었다는 것을 의미
    - 컨테이너: 객체의 생명주기를 관리, 생성된 인스턴스들에게 추가적인 기능을 제공하도록 하는 것
    
    **IoC**: 스프링 프레임워크의 객체를 생성하고 관리하고 책임지고 의존성을 관리해주는 컨테이너
    
    - IoC 컨테이너는 객체의 생성을 책임지고, 의존성을 관리한다
    - POJO의 생성, 초기화, 서비스, 소멸에 대한 권한을 가진다
    - 개발자들이 직접 POJO를 생성할 수 있지만 컨테이너에게 맡긴다
    - 개발자는 비즈니스 로직에 집중할 수 있다
    - 객체 생성 코드가 없으므로 TDD가 용이하다
    - 분류
        - DL: 저장소에 저장되어 있는 Bean에 접근하기 위해 컨테이너가 제공하는 API를 이용하여 Bean을 Lockup하는 것
        - DI : 각 클래스간의 의존관계를 빈 설정(Bean Definition) 정보를 바탕으로 컨테이너가 자동으로 연결해주는 것
        - DL 사용시 컨테이너 종속이 증가하기 때문에 주로 DI를 사용
    
    스프링 컨테이너(IoC**)** 종류
    
    - **BeanFactory**
        - 스프링 컨테이너가 관리하는 객체를빈(Bean)이라고 하고,
        이 빈들을 관리한다는 의미로 컨테이너를 빈 팩토리(BeanFactory) 라고 함
        - BeanFactory 계열의 인터페이스만 구현한 클래스는 단순히 컨테이너에서 객체를 생성하고 DI를 처리하는 기능만 제공
        - Bean을 등록, 생성, 조회, 반환 관리
    - **ApplicationContext**
        - BeanFactory에 여러가지 컨테이너 기능을 추가
            
            →
            
        - 국제화가 지원되는 텍스트 메시지를 관리
        - 이미지같은 파일 자원을 로드할 수 있는 포괄적인 방법을 제공
        - 리스너로 등록된 빈에게 이벤트 발생을 알려줌

- 프레임워크와 API의 차이
    
    ### 프레임워크
    
    - 목적에 필요한 것을 고민할 필요 없이 이용할 수 있도록 일괄로 가져다 쓰도록 만들어 놓은 '구조화된 틀'
    - 만들어진 수단을 가져다가 매뉴얼대로 이용
    - 프로그래밍에서 특정 운영 체제를 위한 응용 프로그램 표준 구조를 구현하는 클래스와 라이브러리 모임

    - 다른 개발자들이 사용할 수 있도록 함수나 메서드, 클래스를 정의

- AOP
    
    스프링 프레임워크에서 **AOP(Aspect-Oriented Programming, 관점 지향 프로그래밍)**는 프로그래밍의 한 패러다임으로, 애플리케이션의 공통 관심 사항(Cross-Cutting Concerns)을 모듈화하는 방법
    
    - AOP를 통해 로깅, 트랜잭션 관리, 보안 등과 같은 공통 기능을 애플리케이션의 다른 부분에 영향을 주지 않고 분리하여 관리
    - 기존의 OOP(Object-Oriented Programming, 객체 지향 프로그래밍)를 보완하는 개념
    - Aspect: 공통 관심 사항을 모듈화한 것으로, 예를 들어 로깅이나 보안 등의 기능을 Aspect로 정의할 수 있음
    - Join Point: Aspect가 적용될 수 있는 위치, 즉 메소드 호출이나 필드 접근과 같은 프로그램 실행의 특정 지점
    - Advice: Aspect의 실제 구현체로, 특정 Join Point에서 Aspect의 코드가 실행되는 시점(예: 메소드 실행 전/후)을 정의
    - Pointcut: Join Point의 부분 집합으로, 실제로 Advice가 적용될 위치를 선별하는 표현식
    - Target: Advice가 적용되는 대상 객체를 의미

- 서블릿
    
    클라이언트의 요청을 처리하고, 그 결과를 반환하는 Servlet 클래스의 구현 규칙을 지킨 자바 웹 프로그래밍 기술
    
    - 웹 애플리케이션에서 클라이언트의 요청을 처리하고, 그에 대한 응답을 생성하는 구성 요소
    - 자바에서 웹 애플리케이션을 만들 때 HTTP 요청을 처리하는 역할
    - MVC 패턴에서 Controller로 이용됨
    - HTTP 프로토콜 서비스를 지원하는 javax.servlet.http.HttpServlet 클래스를 상속받음
